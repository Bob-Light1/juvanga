# JUV-110 — Consented local reading progress validation

Date: 2026-11-07. Owner: Codex. Branch: `feat/JUV-110-consented-reading-progress`. Status: done after technical, privacy-boundary and visual author review.

## Delivered and contract

A noindex `/progress` page and a reader control explain personal-device opt-in, device/browser limits and erasure. No storage probe, identifier, refusal record or progress write occurs before explicit agreement. A single namespaced record retains only the last course ID/version, lesson ID, approximate scroll location and UTC update time. No exercise response, checked criterion, comparison state, score or personal information enters this record. Only reading routes track position. Enabling is idempotent; refusal remains in memory. Matching lessons restore scroll after fonts/layout are ready, and resume always uses the exact retained published version.

Strict allowlist validation rejects malformed, extra-field and incompatible envelopes without deletion/migration. Unknown content versions offer a catalogue route and erasure, without switching the user to newer content. Storage access/quota failures do not block reading or exercises. Erasure removes only the application's key, stops pending writes and preserves unrelated data; failed removal explicitly warns that data may remain and does not re-enable tracking on a refresh. Each save rechecks durable consent; storage events synchronize revocation across tabs. Dates display with the existing Douala Intl helper. Static rendering never accesses browser storage or embeds saved personal state. [ADR-012](../architecture/decisions/012-local-progress.md).

## Limits

Not run: deployment or actual hosting/header verification, remote CI, physical-device/non-Chromium/screen-reader software checks or independent learner usability review. Browser tests simulate storage API failures; they do not establish behavior in every private-browsing implementation. Scroll restore is approximate and can shift after viewport/media layout changes. No offline guarantee, account synchronization, M1 import or expiry policy is added. A failed erasure may leave an existing record until the user retries or clears site data; the UI states that limit. The real course remains unpublished.
