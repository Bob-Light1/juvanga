# Working instructions — Juvanga

## Minimal session restart

Read this file, `docs/STATUS.md`, then the current ticket (`npm run task -- JUV-xxx`). Read only references relevant to that ticket. Do not reread PDFs, the entire backlog or the lockfile by default. `npm run context` is the short entry point.

## Sources of truth

- Requirements: `docs/product/BRIEF.md`, `SCOPE.md`; product decisions: `DECISIONS.md`.
- Technical decisions: `docs/architecture/decisions/`. Every structural change needs an ADR covering alternatives, consequences and migration.
- Tasks: `docs/backlog/backlog.json`. Markdown and CSV are generated by `npm run backlog:generate`; do not edit them directly.
- Live state: `docs/STATUS.md` (aim for fewer than 700 words). Handoffs: `docs/sessions/`; keep a concise history, not a chat transcript.

## Execution and cooperation

One ticket, one owner, one `feat/JUV-xxx-description` branch. Record owner, branch, date and status before editing shared files. An active task must have all dependencies completed. After an interruption, do not assume an active task still belongs to its previous owner: contact that person or record reassignment.

Do not overwrite another developer's changes or modify secrets. Do not add a framework for local convenience. This file does not request delegation to agents.

Documentation, code, identifiers and code comments must be in English. This includes inline comments, block comments and documentation comments. The initial product interface remains in French. Product text belongs in the i18n catalogue planned by JUV-107. Use shared CSS tokens. Store dates in UTC, display them in `Africa/Douala`, and use integer XAF amounts. Published course versions and rubrics are immutable.

Payment evidence ≠ receipt of funds; order ≠ booking; booking ≠ learning access. Never grant paid access from a screenshot alone. Financial entry and approval require two distinct people. Authorize every resource on the server; never rely on a hidden button.

## Validation and session close

Run `npm run verify` and tests relevant to the ticket. Do not claim a test was run if it was only described. `done` requires evidence, satisfied criteria and the necessary review. Update the backlog, STATUS, decisions and a short handoff. Explicitly identify checks that were not run.

No implicit deployment in build scripts. Never put a secret in a `VITE_*` variable. Future features requiring a provider account remain marked as not configured until actually verified.

## Context efficiency

Search with `rg` and read targeted excerpts. Keep each canonical fact in one place and link to it elsewhere. Do not copy full histories or test output. Summarize command, result, limitations and evidence location. Do not repeat recent provider research without a reason; record source and date in `docs/SOURCES.md`.
